# interview-knowledge 总览与学习路线

> 这份总览不是讲知识点本身，而是告诉你：**这套文档为什么这样组织、先学什么、后学什么、每篇解决什么面试问题、如何把整个项目讲成一套完整故事。**
>
> **审校状态（2026-04-03）**
> - `10` 到 `15` 是这套材料里**权重最高**的“当前仓库真相层”，优先级高于旧的长文档。
> - `01/02/05/09` 含有少量**扩展设计**或**旧仓库事实**，现在已经过审校，但学习时必须区分“当前已实现”和“面试扩展知识”。
> - 如果不同文档之间出现冲突，以 `10` 到 `15` 和当前仓库代码为准。

## 一、先给结论：这套文档的真正主轴是什么？

这套文档不是平均发力的。

**真正的主轴只有 5 条：**
1. **RAG 与知识库工程化**
2. **后端架构与服务治理**
3. **数据库与高并发设计**
4. **Redis 与缓存/锁/限流/高可用**
5. **异步任务系统与可靠性**

其他内容——认证安全、前端、部署——都重要，但它们更多是：
- 横切能力
- 配套能力
- 项目完整性的补充

所以你学习时不要平均分配精力。**主力必须打在 RAG + 后端。**

## 二、这套文档解决的不是“会不会用”，而是“能不能讲深”

很多人学项目，只能回答：
- 我用了 FastAPI
- 我用了 Redis
- 我做了 RAG
- 我用了 pgvector

这种回答很浅，面试官追问两轮就没了。

这套文档的目标是把你的表达升级成三层：

### 第 1 层：项目里怎么做
- 我们的链路是什么
- 用了哪些组件
- 数据怎么流转

### 第 2 层：工程上为什么这样做
- 为什么是这个方案
- 替代方案是什么
- 这里的取舍和边界是什么

### 第 3 层：中高级面试怎么答
- 如果放大规模怎么办
- 如果故障发生怎么办
- 如果面试官追问一致性/性能/可用性怎么办

**一句话：你不是在背知识点，你是在训练“架构化表达能力”。**

## 四、每篇文档分别解决什么面试问题

### 1) `01-RAG-检索增强生成.md`
**你要靠它回答的问题：**
- 你的 RAG 系统完整链路是什么？
- 为什么要 chunk？为什么要 embedding？
- 为什么混合检索？为什么还要 rerank？
- 怎么做 query rewrite？怎么做路由决策？
- 如何评估 RAG 的效果？
- RAG 和微调、ES、纯向量检索怎么选？

**这一篇是整套文档的 AI 核心。**

### 2) `04-异步任务与目标检测.md`
**你要靠它回答的问题：**
- 为什么重任务要异步化？
- API 和 worker 怎么分工？
- 任务怎么重试？怎么避免重复执行？
- at-least-once 是什么意思？
- 死信队列、积压、幂等怎么做？

**这一篇是“系统不是 demo，而是工程系统”的关键证明。**

### 3) `05-数据库与ORM.md`
**你要靠它回答的问题：**
- 为什么选 PostgreSQL？
- ORM 的本质和代价是什么？
- 什么是 MVCC、WAL、Checkpoint？
- 什么是死锁？怎么避免？
- 慢查询怎么查？索引怎么设计？
- 什么时候该分区、读写分离、分库分表？

**这一篇是你后端硬实力的核心。**

### 4) `06-Redis.md`
**你要靠它回答的问题：**
- Redis 为什么快？
- Redis 在项目里除了缓存还做了什么？
- 缓存一致性怎么做？
- 缓存穿透/击穿/雪崩怎么处理？
- 什么是 Hot Key / Big Key？
- Sentinel 和 Cluster 的区别？
- 为什么 Lua 脚本比事务更适合某些原子操作？

**这一篇最适合拉开你和普通 CRUD 候选人的差距。**

### 5) `07-FastAPI与后端架构.md`
**你要靠它回答的问题：**
- FastAPI 和 Flask 的本质区别是什么？
- ASGI 为什么适合高并发 I/O？
- 流式响应为什么容易被代理层搞坏？
- 幂等、超时、重试、熔断、降级分别解决什么问题？
- 什么是可观测性？为什么 request_id / trace_id 重要？
- 健康检查、发布、回滚、资源隔离怎么设计？

**这一篇决定你能不能把“会用框架”讲成“懂后端工程”。**

### 6) `02-认证与安全.md`
**你要靠它回答的问题：**
- JWT 和 Session 怎么选？
- 为什么密码要哈希？为什么选 Argon2id？
- 黑名单怎么做？
- Prompt 注入怎么防？
- RBAC / ABAC 是什么？
- Access Token / Refresh Token 怎么设计？

### 7) `08-系统设计方法论.md`
**你要靠它回答的问题：**
- 系统设计题怎么开场？
- 怎么问需求和非功能指标？
- 怎么做容量估算？
- 怎么拆层？怎么识别瓶颈？
- 怎么回答“高并发、扩容、降级、回滚、补偿”？

**这一篇是把前面所有单点知识串起来的总方法。**

## 五、推荐学习顺序：不要乱看

### 第一阶段：先把“项目真相”讲准
按这个顺序看：

2. `12-聊天链路失败模式与排障画像.md`

4. `13-第一次真实Baseline结果与改进优先级.md`
5. `14-第二次Baseline与历史污染修复.md`
6. `15-评测口径校准与最终Baseline.md`

为什么先看这 6 篇？
因为它们直接告诉你：这个项目现在真实做到哪一步、怎么测、怎么挂、怎么修。

### 第二阶段：再把后端底座打牢
按这个顺序看：
7. `07-FastAPI与后端架构.md`
8. `05-数据库与ORM.md`
9. `06-Redis.md`

为什么先看这 3 篇？
因为不把后端底座打牢，后面 RAG、异步任务、知识库治理都会变成“会背流程，不懂本质”。

### 第三阶段：再学系统如何承载 AI 能力
10. `04-异步任务与目标检测.md`
11. `01-RAG-检索增强生成.md`

这个顺序不是反的。
先任务系统，再 RAG，是因为：
- 你先理解“服务如何承载重任务”
- 再理解“RAG 这条 AI 链路具体怎么组织”

### 第四阶段：补高阶抽象
12. `02-认证与安全.md`
13. `08-系统设计方法论.md`

最后再用系统设计方法论，把前面所有知识串成一套完整答题框架。

### 第五阶段：补充前端和冲刺材料

## 七、怎么把整个项目讲成一条完整故事

这是最关键的一部分。

你不能把项目讲成：
- 一会儿讲 FastAPI
- 一会儿讲 Redis
- 一会儿讲 RAG
- 一会儿讲 Docker

这样会很散。

你应该把它讲成一条链：

```text
用户请求进入系统
  -> FastAPI 接口接入
  -> 认证 / 限流 / 参数校验
  -> 如果是聊天问题：进入 RAG 链路（检索 / 重排 / 生成 / 流式输出）
  -> 如果是图片检测或知识库重建：进入异步任务链路（API 入队，Worker 执行）
  -> PostgreSQL 负责事务真相源
  -> Redis 负责缓存、锁、限流、短时状态、队列底座
  -> Nginx / Docker 负责部署与边界
```

这条链讲顺了，你的项目就不再是“功能列表”，而是一个完整系统。

## 九、学习时最容易犯的错误

### 错误 1：平均发力
你不是在准备百科全书。主轴必须突出，不要把时间平均给前端、部署、UI 细节。

### 错误 2：只背“项目里用了什么”
面试官真正想听的是：
- 为什么这么选？
- 有什么代价？
- 规模放大怎么办？
- 出故障怎么办？

### 错误 3：只看实现，不看抽象
只会背接口和代码，回答会非常碎。

### 错误 4：只会正常路径，不会失败路径
不会讲超时、重试、回滚、补偿、降级，系统设计一定吃亏。
