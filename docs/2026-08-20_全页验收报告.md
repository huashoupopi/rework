## 🔴 P0：聊天页布局塌陷（一个根因，三个症状）

### 实测证据

```
文档高 15536px，视口 1005px，打开聊天页自动滚到 14356（底部）
「新建」按钮   top = -10079px   ← 滚出视口一万像素
会话列表       top =  -6361px   ← 看不见
输入框         top =    857px   ← 只有它在视口内

删除按钮尺寸 = 21 × 1245 px
document.elementFromPoint(按钮中心) → null，isSelf: false
hook XMLHttpRequest 后点删除 → 发出 0 个请求
```

### 根因（布局链实测）

```
.chat-layout            h=14893  display:grid   ← 无高度约束，跟随内容
  .chat-sidebar         h=14893                 ← 侧栏被拉到与整页等高
    .chat-sidebar__list h=7518   overflow:auto  ← 有 overflow，但父级无固定高度 → 永不触发
      LI                h=2493   display:grid   ← 3 个会话平分 7518
        .chat-sidebar__actions  h=2493
          BUTTON        h=1245                  ← grid 拉伸，图标按钮成了 1245px 高
```

**`overflow: auto` 写了但没用**——它需要一个确定的高度才会产生滚动条。父链一路无约束，于是整条侧栏跟着消息区一起被撑开。

### 修法方向

给聊天布局固定视口高度（如 `height: calc(100vh - 顶栏高)` 或 `min-height:0` + `grid-template-rows`），让**消息区独立滚动、侧栏固定不动**。
⚠️ 注意 grid 子项默认 `min-height:auto` 会阻止收缩，需显式 `min-height: 0`。

### 验收口径

- 打开有长历史的会话，`window.scrollY` 应为 0，页面本身不滚动
- 「新建」按钮与会话列表始终在视口内
- 删除按钮 `getBoundingClientRect().height` < 50px
- 点删除能发出 `DELETE /api/conversations/{id}` 请求

## 🟠 P1：任务中心统计口径失真

### 实测证据

```
第 1 页：已加载 10 条任务，当前页完成 10 条 | "当前批次 10 条任务" | 表格 10 行
第 2 页：已加载  6 条任务，当前页完成  1 条 | "当前批次  6 条任务" | 表格  6 行 | 第 2/2 页
```
**「当前批次」随翻页从 10 变成 6** —— 那不是批次，是当前页条数。

```
在第 2 页（共 6 条）上筛选：
  筛「失败」  → 5 行
  筛「已完成」→ 1 行        5 + 1 = 6 = 当前页全部
  文案始终是「已加载 6 条任务，当前页完成 1 条」，不随筛选变
```

**筛选只作用于当前页已加载的数据**，不是全库。总共 16 条、实际完成 11 条，但「完成率」等指标永远只按当前页算；要找出所有失败任务必须一页页翻着筛。

### 修法方向（二选一，执行前先说选哪条）

- ⑴ **筛选与统计下沉服务端**：状态筛选走查询参数，统计走独立聚合接口（正道，backlog 原判）
- ⑵ **先改口径不改架构**：把「当前批次」「完成率」明确标注为「当前页」，并让文案随筛选更新（成本低，但没解决"翻页才能找全"）

⚠️ 若选 ⑵ 必须在 backlog 保留 ⑴，⛔ 不得以「文案改了」为由划掉那条账。

### 实测证据（各页残留的英文枚举）

```

/tasks/56             completed, corrosion      ← 缺陷类型
/knowledge/documents  active, deleted

```

**`TaskTable.jsx` 里已有 `craze→裂纹`/`corrosion→腐蚀` 映射**（批次 0 复验时确认过），但任务详情的结果概览、文档列表状态、重建页文档状态都没做映射，直接渲染后端英文值。

⛔ 不许各页再各写一份 —— 那正是现在有的地方有、有的地方没有的原因。

## 🟡 P2：两个小问题

### ~~hover 按钮读屏念两遍~~ ⛔ 本条误判，已撤回
初判依据是 `innerText` 输出「上传检测任务上传检测任务」。
**复核代码后作废**：`InteractiveHoverButton` 的第二层 div **本来就有 `aria-hidden="true"`**，
读屏器只念一遍。`innerText` 不理会 `aria-hidden`，那是 DOM API 的行为，与用户无关。
🪝 **教训：用 `innerText` 判断无障碍问题是错的尺子** —— 要看无障碍树，不是文本快照。

### 窄屏布局重叠
390px 宽度下：`sidebar` 与 `main` 均为 `362px @left14`，完全重叠。
本项目定位为桌面端求职作品，**优先级最低**，记账即可。
